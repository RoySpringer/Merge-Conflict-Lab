3Beoordelen
DENK EERST

Niet klikken, maar begrijpen

Nog te doen
De situatie

Je werkt met je team aan een softwareproduct waarmee studenten zich voor workshops inschrijven. Na een review vraagt de klant om de capaciteit te verhogen van 24 naar 30 plaatsen. Zodra er 30 deelnemers zijn, mag niemand meer inschrijven. Jij en een teamgenoot hebben allebei dezelfde functie aangepast; daardoor ontstaat dit conflict.

Welke aanpak past bij de bedoeling?

HEAD
const limit = 24;
return participants.length < limit;
feature/capacity-30
const limit = 30;
return participants.length <= limit;

Wat doe je bij een merge-conflict?

Nog te doen
De situatie

Je teamgenoot heeft nieuwe code gepusht. Jij haalt de wijzigingen binnen met git pull. Git stopt: in capacity.js zit een merge-conflict. Zet vanaf dat moment de acties in de juiste volgorde.

Klik steeds de eerstvolgende actie aan.

Jouw volgorde

Debrief

Kun je het straks zonder deze site?

Een merge-conflict is geen puzzel met altijd één “juiste” branch. De code moet één samenhangend resultaat vormen dat past bij de bedoeling en door de tests komt.

status → begrijpen → oplossen → testen → toevoegen + committen
